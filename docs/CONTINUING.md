# Setup and backup notes

The October 14, 2026 backup contains the desktop kiosk source and water refinement, menu assets, concept art, visual review captures, and earlier local snapshots. Git history preserves the repository's earlier published versions.

## Run on another computer

Follow the clone and local server commands in the root README. There is no application build step or runtime package installation. A modern browser with WebGL animates the water. Without WebGL, the static poster and CSS touch effect remain available. Reduced-motion preferences stop the water animation.

For Linux with Chromium installed, run the checked-out version directly:

```bash
GAIA_UI_DIR="$PWD" bash scripts/gaia-kiosk
```

The launcher uses a separate Chromium profile and prevents duplicate kiosk instances. It expects `/usr/bin/chromium` and `flock`. For a permanent installation, copy the application to `~/Applications/gaia-ui`, install the launcher at `~/.local/bin/gaia-kiosk`, and point a desktop shortcut to that launcher. The default application path is `~/Applications/gaia-ui`; `GAIA_UI_DIR` can override it. No browser profile, saved credentials, or machine logs are included in the repository.

The existing kiosk on the original Pi loads the installed copy, not the source checkout. After future source changes, copy the changed application files into the installed directory and reload the kiosk. Preserve the installed browser profile separately.

## Work from multiple computers

1. Pull the latest changes before editing: `git pull --ff-only`.
2. Make and visually check changes in a browser, including touch orientation, demo states, and D-toggle behavior when affected.
3. Review `git status` and `git diff`, then commit the intended files.
4. Push to GitHub. Wait for **Deploy GAIA UI and refresh download** to finish.
5. Pull once more to receive the automated ZIP update before switching computers.

Branches are useful for experiments. The `main` branch is the current shared version and automatically publishes the website. GitHub authentication for pushing is configured separately on each computer.
